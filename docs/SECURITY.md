# Security

## Final product-pass viewer boundaries

Feed, command arguments and Producer input share one category-aware moderation policy. Every hate, harassment, sexual/minors, self-harm and illicit flag blocks input. Graphic violence flags or scores at least 0.5 also block. A violence-only flag may pass for clearly identified fantasy game actors, with real-person targets and direct threats excluded. Local rules additionally reject explicit sexual requests, spam, ads and host-manipulation requests even if the model does not flag them. Missing categories/scores or provider failures fail closed. This is a narrow game-combat exception, not a general exemption for text mentioning a game. The [26-case live verification](media/moderation-live-report.json) includes both actual dragon submissions; it is a measured regression check, not a guarantee against every possible harmful message.

New feed entries are queued in bounded batches and are visible only after both the local rule layer and `omni-moderation-latest` succeed. Provider errors clear the visible feed and fail closed; the in-memory cache is bounded and is discarded at restart. The dashboard inbox is a local administrative surface and may contain pending unmoderated ideas. Viewer display names pass a local rule before entering worker snapshots, event callbacks and credit formatting. Text arguments to mod commands are checked before dispatch; empty-argument commands remain available if moderation is unavailable.

The live build display is not raw Codex output: it reads only the candidate mod path, rejects symlinks and overlarge files, then removes comments, free-form strings and unknown identifiers before sending a maximum of 14 bounded lines. Sprite previews are bounded numeric pixels and validated hex colors. The workspace and authoring process remain untrusted, and text filtering and model moderation cannot prove the absence of all harmful or adversarial content. The existing QuickJS, Gatekeeper, local-origin and Builder sandbox boundaries still apply.

## M3 AI and prompt injection

Viewer ideas/names, model cards, source and `forgeTest` are untrusted. The Producer applies host/real-world/ads/spam rules and `omni-moderation-latest`; provider failure fails closed. Viewer text is serialized as data under a system instruction and compact Mod API summary. Server-assigned group IDs resolve to actual contributors, preventing invented attribution. Empty-credit cards are labelled Forge suggestions. Moderation and prompts are not sandbox boundaries.

Builder uses a dedicated ignored Codex home, a copy of the existing login, and a minimal OS environment without OpenAI/Twitch keys. Apps/plugins, remote plugin discovery, multi-agent and web search are disabled. Explicit native Windows sandbox selection enables the SDK's `workspace-write` policy; command network access is off and approvals are `never`. References have integrity hashes; a manifest rejects unexpected writes, tampering, symlinks and excessive files/nesting/size. Trusted host-side Gatekeeper rechecks source independently of the Builder's own CLI result. Global Codex configuration is unchanged.

**Scope:** workspace-write restricts writes, not all filesystem reads. Reference hashes are admission checks, not OS read-only ACLs. This implements the brief's policy; a hostile Builder requiring deny-by-default reads needs a separate least-privilege account/container or a tested custom permission profile. No-network, minimal inherited secrets and disabled connectors reduce exposure; local account/SDK remain trusted infrastructure. Do not claim complete protection against local credential reads.

HUD activity is allowlisted generic categories only. Raw reasoning, prose, commands/output, provider bodies and MCP payloads are never forwarded. Bounded Gatekeeper diagnostics render as text. Explicit `.env` credentials override a parent tool's injected credentials; a regression test covers the mismatch that initially caused a false credit-exhaustion diagnosis.

Acorn checks at most 24 KiB and requires direct named `register` and literal `forgeTest`. Imports, host globals, eval/constructors, async/Promise/WebAssembly, prototype tricks and dynamic computed properties are forbidden. Candidate source runs only in QuickJS. Two 900-tick runs use the current checkpoint/mod set and check budgets, exceptions/rollback, entity/rule invariants, equal hashes, registered card commands and candidate-owned observable effects. Other live mods and invisible zero-strength FX cannot satisfy acceptance. English acceptance prose is not a formal semantic proof; the explicit `forgeTest` claims are machine-checked.

One build slot, a four-minute total deadline, two repair retries and an hourly cap bound AI work. Live failure restores the failed version's pre-deployment checkpoint; Safe Mode restores the seed baseline. Full rollback history persists across restart. Forge controls remain local JSON POSTs behind Host/Origin/remote checks; the overlay receives no source, checkpoint or auth data. Test discovery excludes `runtime/`, including SDK caches and generated code.

## Threat model

Twitch viewers control text, names and events. Generated mod code is untrusted and may try to escape, exhaust CPU/memory, alter host objects, corrupt persisted state or attack the overlay. Developer endpoints are powerful local controls.

The [September 2026 SCRT research](https://blog.scrt.ch/2026/09/22/how-one-twitch-chat-message-became-code-execution-on-a-streamers-pc/) demonstrated overlay XSS chained with a Chromium vulnerability. ChatForge renders all viewer-originated strings with canvas `fillText` or DOM `textContent`, never `innerHTML`.

## M1 boundaries

- Server binds `127.0.0.1`. Dev mutations require JSON and an allowed localhost Vite Origin; disabled in production. `/dev/populate` is a bounded performance fixture (1–300 durable heroes), not a remote spawning API. The read-only WebSocket sends render fields only.
- Simulation runs in a Node worker. Each mod runs in a separate QuickJS runtime with no module loader, host globals, network, filesystem or native timers. `process`, `require`, `fetch`, DOM, Buffer and host global objects are absent. Static imports fail; pending asynchronous jobs/dynamic imports are rejected without execution.
- Date, Math.random, eval and function constructors (including async/generator constructor paths) are disabled. Mod runtime intrinsic objects/prototypes and control entry points are frozen. The bridge is captured and removed from the guest global object.
- The bridge exchanges bounded JSON strings. Every host operation validates phase, names, shape, ownership, finite numbers and quotas. Guest values never become host functions. State rejects cycles, accessors, functions, non-finite values, unsafe prototype keys and non-plain objects.
- Runtime limits: 4 MiB memory, 256 KiB stack, 50 ms registration, 20 ms aggregate thread CPU execution per mod per simulation tick (60 ms in noisy CI). The interrupt handler stops runaway bytecode; validated host work is bounded separately (128 writes / 256 calls per invocation). Full limits are in MOD_API.md.
- World mutations, schedules and RNG changes are buffered and commit only after success and state validation. Catching quota errors does not permit partial commit. Failure restores a complete checkpoint and re-registers its source set; errors carry mod ID/message/guest stack outside world state and produce an overlay rollback banner.
- Secrets remain in ignored `.env`; runtime data remains in ignored `runtime/`. The Codex Builder default remains explicit `gpt-6.1-sol` with the machine's ChatGPT login; global Codex config is unchanged.

## Verification and scope

Tests cover process/require/fetch/host globals, static and dynamic import, Function/eval constructor paths, Date/random, infinite loops, recursion, huge allocation, prototype pollution, registration mutations, oversized/non-JSON state, async jobs, cumulative CPU budgets and buffered command/schedule floods. Rollback tests compare the entire pre-deployment hash and deterministic continuation of multiple mods, schedules and cooldowns. Snapshot spies ensure normal ticks do not deep-copy the world.

These are tested isolation boundaries, not a proof against all QuickJS/WASM vulnerabilities. The worker is a responsiveness boundary, not an OS security sandbox. The local user and files under runtime/mods are trusted inputs to deployment; a malicious local program can impersonate allowed HTTP headers. Gatekeeper adds static analysis and admission. Browser FPS depends on hardware and is measured locally; CI enforces simulation thresholds on both operating systems.

CPU accounting uses Node 24's [process.threadCpuUsage](https://nodejs.org/docs/latest-v24.x/api/process.html#processthreadcpuusagepreviousvalue), excluding OS descheduling. A secondary wall deadline (at least 250 ms) also bounds each evaluation. Windows CPU timer granularity can overshoot a CPU limit by one OS accounting quantum. Performance gates independently measure real elapsed tick time.

## M2 OAuth, tokens and chat threat model

| Threat / untrusted input                        | Boundary and behavior                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Forged/replayed OAuth callback                  | Cryptographically random 256-bit state, five-minute TTL, consumed once, bound to a separate random HttpOnly SameSite=Lax browser cookie. Login canonicalizes the callback host before issuing the cookie. Invalid state is rejected before token exchange.                                                                                                                     |
| Token/code disclosure                           | Credentials stay in ignored `.env`; tokens in ignored `runtime/secrets/twitch.json`, atomic replace with restrictive POSIX mode. Status only exposes account, expiry, health and configured boolean. Upstream token/error bodies, codes and request URLs are never logged or returned.                                                                                         |
| Expired or revoked authorization                | Validate at startup/hourly; check user/client/scopes. Refresh near expiry and after 401, single-flight refresh and one API retry. Failure or revocation stops EventSub and clears outgoing chat; dashboard asks to reconnect.                                                                                                                                                  |
| Cross-site local administration / DNS rebinding | Bind 127.0.0.1; verify remote loopback address, exact Host, allowed Origin and Fetch Metadata. Mutations require JSON and an allowed Origin. No wildcard CORS. OAuth top-level login/callback navigation may cross hosts; browser-bound state still protects the callback.                                                                                                     |
| Overlay/client attempting commands              | WebSocket is snapshot-only, Origin/Host checked, inbound application messages close with policy code 1008. No tokens or admin state in snapshots.                                                                                                                                                                                                                              |
| Reconnect URL / malformed notifications         | Only the official EventSub host/protocol (or injected fake test server) can supply a reconnect target. Zod envelope/domain validation and 128 KiB socket payload cap. Stale/future messages rejected; persisted message-ID receipts prevent duplicate processing within the delivery window.                                                                                   |
| Viewer text / prompt injection                  | NFC normalization, control/format/zero-width/bidi removal, whitespace collapse, bounded Unicode lengths. Links and emote-only ideas rejected; cooldowns, dedupe and round cap. React text children and Canvas fillText only; no HTML insertion. Pending ideas are data, not approved instructions or runnable mods. M3 must moderate them before Producer/Builder consumption. |
| Simulator masquerading as real chat             | Source remains explicit through routing, database, worker, snapshot and display. SIM tags cannot be user-selected off. Outbound queue rejects simulator source, including help/status replies.                                                                                                                                                                                 |
| Chat flooding / excessive sends                 | Bounded local log/inbox cache/queue; per-user routing cooldowns; 200 ideas per round. Outbound spacing, 60-second same-message dedupe and HTTP 429 backoff. Never resend ambiguous failed requests automatically except an explicit rate-limit refusal.                                                                                                                        |

Windows does not enforce POSIX `0600` as an NTFS access-control list. Token confidentiality on Windows relies on the current user's profile/folder ACL; local programs running as that user are trusted. The token file is local plaintext by design, not an encrypted vault. Do not copy `runtime/` into screenshots, issue attachments or public bundles. The dashboard does not authenticate separate OS users; localhost access is the stated trust boundary.

The six requested scopes include `user:bot`; user-token chat and WebSocket subscriptions use the logged-in streamer's identity. We do not request native polls, predictions or extra channel administration. A non-affiliate refusal is a capability state, not a fatal auth error. Chat sends with a user token can propagate to Shared Chat channels under Twitch's API behavior; the human test instructions call this out.

Fake HTTP/WebSocket tests cover OAuth CSRF expiry/reuse/browser mismatch, startup/hourly validation, proactive/401 refresh and safe failures, subscription timing/conditions, keepalive timeout, handoff without duplicate subscriptions, notification dedupe and revocation. Router tests cover Vietnamese/CJK, emoji, controls, links, cooldowns, persistence, SIM determinism and outbound limits. The browser hand-off smoke never completes login or sends real chat. Actual account permissions and live delivery remain for the human [live test](LIVE_TEST.md).

## M4 visual and Builder boundaries

All v1.1 effects are validated host transactions invoked from QuickJS: finite coordinates/durations, bounded scale, palette-only colors, four sky themes and four synthesized audio cues. Invalid operations roll back the entire callback. Props have no combat AI; cosmetic sprites must belong to the calling mod. No URLs, media downloads, HTML, host code evaluation or new network permissions are introduced. Audio starts muted and requires a user gesture.

The Builder uses an isolated Codex home, plugins/apps/remote plugins disabled, no configured MCP servers, bundled skills disabled and explicit disabled entries for discovered local skills. Skill dependency installation is off. Windows native sandbox binaries are necessary and can regenerate; cleanup uses an exact two-cache allowlist with symlink/junction ancestor checks. Login, session logs, SQLite and workspace references are never cleanup targets. Tests exercise preserved sentinel files and a junction escaping the fixture root.

Baseline host faults are separated from candidate failures before any paid Builder turn. The same immutable admission snapshot and harness serve CLI and host. Actual Gatekeeper checks are streamed; the UI never invents passing checks. Spectacle scoring measures observable activity, not artistic quality or a formal proof of the English card's meaning.

## M5 hardening

The server sets a same-origin Content Security Policy, restricts connections to localhost, blocks objects, and sends `X-Content-Type-Options: nosniff`. The browser smoke checks these headers and reconnection behavior. The readiness display distinguishes a configured local Codex login file from a verified login; the OpenAI key check is opt-in and does not expose provider response bodies.

Abuse coverage includes instructions to disclose environment variables or an API key, infinite loops, markup and bidi controls, and flooding. Known malicious ideas are rejected before model submission. A real Producer/moderation drill includes one safe idea and confirms the three hostile ideas are filtered; this is not a penetration test of an unrestricted Builder. Gatekeeper and QuickJS independently remain mandatory admission and execution boundaries. Simulated credits use the shared `@name (SIM)` formatter, including generated-banner admission checks.

`node scripts/scan-runtime-secrets.mjs` scans runtime text and SQLite content for credential-shaped text and matching configured secrets without printing their values. It skips the actual credential store and temporary active-work directories; a clean result is limited to these patterns and paths. Dependency audit results and actual long-stream results are recorded in the journey rather than asserted here.
